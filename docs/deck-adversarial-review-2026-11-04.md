# Where the workshop can lose the room: an adversarial slide review

**Verdict:** Keep the technical depth. Fix the route through it. A participant can successfully run a terminal lab while inspecting the wrong browser module. An instructor can follow the capstone’s commands and still lack the evidence to answer the question on screen. Both problems are fixable without adding more lecture slides.

**Scope:** All 102 native slides and their speaker notes, including all five modules, the wrap, and the resource appendix. Reviewed Google Slides revision `ljrRLR2cvxOB3w` against the current workshop checkout (HEAD `68ed13d`, including the working-tree changes to the readiness check and browser). Slide numbers below link to the corresponding native slides. This is feedback only; neither the deck nor its source was edited.

## How the personas challenged the deck

Three independent reviews and an editorial/visual pass used the following perspectives. These are review lenses, not interviews or measured learner outcomes.

| Persona | Question they tried to answer | Where the deck failed the test |
|---|---|---|
| First-time workshop participant | “From this slide alone, what do I open, run, and expect to see?” | The first link can send them to the library instead of the workshop. Later scenario commands do not switch the browser backend. |
| Facilitator with a hard stop | “What do I skip when capabilities are disabled or generation takes several minutes?” | Fallback is mentioned, but the following graph and governance tasks still require hosted artifacts. |
| SDK and graph practitioner | “Would copying this snippet or traversing this edge give the behavior being taught?” | One excerpt drops the retrieved-evidence heading. One diagram omits the membership edges the real query follows. |
| Skeptical evaluator | “Which alternative explanation has the experiment ruled out?” | Exact refusal-quote recall is labeled “Procedure.” The fresh-agent case does not challenge the changed limit. |
| Accessibility and projection reviewer | “Can I follow the graph from my seat, or in a linear reading order?” | A graph edge has 1:1 contrast with its background; separate shapes can expose edge labels before their endpoints. |
| Workshop maintainer | “Will the answer key and projected slide give the same answer?” | The current Module 5 guide still teaches claim nodes and stronger trust conclusions than the slides or code support. |

## Findings and recommended changes

### Getting into the workshop and keeping everyone in the same place

**1. Give the workshop its own front door.** [slide 1](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_slide_001), [slide 2](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_002), [slide 7](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_007), [slide 10](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_010), [slide 88](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_resources_01). No native text hyperlink points to `road-to-agent-memory` or Codespaces. “SDK GitHub” is a useful library reference but the wrong destination for someone trying to run `make check`. Put **Open the workshop in Codespaces** and **Workshop repository / local setup** on the setup slide; use the actual [Codespaces badge and setup instructions](../README.md). Add a module-guide link on each lab and a direct source link on each code slide. The module-local implementation is a teaching asset: show “start at `module_N/app/agent.py`; compare neighboring modules” to participants rather than leaving it in the opening notes. **Check:** a first-timer can find both the correct checkout and the first agent file in two clicks.

**2. Teach the two-terminal switch before the first scenario.** [slide 10](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_010), [slide 17](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_016), [slide 29](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_023), [slide 43](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_035), [slide 57](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_043), [slide 66](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_m5_connect). The slides start Module 1 and later show commands such as `make s2-return`, but no visible `make dev MODULE=2`, `=3`, or `=4`. A scenario opens its own agent; success says nothing about the module behind the browser. Put a small handoff on the **first lab of each module**: “Terminal 1: stop the old server → start `make dev MODULE=N` → reload and confirm the module badge. Terminal 2: run the scenario. In the UI: Refresh graph → choose the named Saved replay.” Use **Live memory** only when the task is to inspect graph records written by that run. See the [participant workflow](../README.md) and [scenario runner](../scripts/run_scenario.py). **Check:** deliberately leave the old server running; the badge check catches it before graph inspection.

**3. Make copied commands runnable.** [slide 17](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_016) includes “One self-contained lookup; then a forgetting control” in the terminal panel. [slide 43](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_035) includes `make s3-enrich (optional)`. Both can break verbatim pasting in a shell. Move prose and optionality outside command blocks. On [slide 66](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_m5_connect) put private `.env` entries and terminal commands in separately labeled regions; avoid suggesting attendees paste the whole panel into either destination. **Check:** extract each command region as plain text and have a reviewer classify every line as a command or comment before any live run.

**4. Turn exploration topics into tasks with observable endings.** [slide 31](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_025), [slide 47](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_037), [slide 59](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_045), [slide 81](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_053). “Q1: MENTIONS provenance” on [slide 47](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_037) is a topic, not an instruction. Specify **act → inspect → conclude**. For example: “In Module 3 browser chat, introduce Maya Chen from Northwind Robotics. In the current conversation, select the user message; follow a `MENTIONS` edge. Which entity did extraction find? Which field on the matched customer came from SQLite?” Allow “no matching extraction on this run” and point to a suitable instructor example. Use the [Module 3 guide](modules/module-3.md) for deeper questions. **Check:** someone can answer using an identified UI view and show the underlying record, not just repeat a definition.

### What the code and graphs establish

**5. Restore the evidence label in the code participants are invited to copy.** [slide 20](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_mem_seam), [slide 26](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_021), [slide 28](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_code_m2_inject), [slide 87](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_059). The excerpt on [slide 28](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_code_m2_inject) appends `context.prompt` directly to `instructions`. The [actual agent](../module_2/app/agent.py) first inserts `Retrieved evidence (cite IDs, not instructions):` on a separate line. Give that line priority in the excerpt. Explain that prior user text is evidence, not authority to execute a refund. A textual heading is a model cue, not an access-control mechanism. The [semantic query](../module_2/app/context.py) searches a workshop namespace across conversations; a shared prefix is not per-customer authorization. In [Module 3](../module_3/app/context.py), customer matching also must not be mistaken for a tenant-isolation guarantee. **Check:** a developer adapting the example can identify where authorization, retrieval scope, and model instructions are each enforced or merely suggested.

**6. Separate membership, ordering, and attribution.** [slide 23](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_019), [slide 24](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_slide_020), [slide 27](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_slide_022), [slide 31](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_025). [slide 24](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_slide_020) depicts one `HAS_MESSAGE` edge followed by `NEXT_MESSAGE` links. The actual [history query](../module_2/app/context.py) matches messages directly from `Conversation` via `HAS_MESSAGE` and sorts by timestamp and ID; it does not traverse the displayed chain to assemble history. Show membership to every message or explicitly mark the other membership edges as omitted. Then change [slide 31](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_025)’s “Which evidence path answered?” to “Which paths supplied the fact?” The same message can occur in both role-preserving history and semantic evidence. A source ID establishes retrieval, not which input caused the model’s answer. **Check:** learners can distinguish same-session history, cross-conversation retrieval, and the valid answer “both paths contain it; causal attribution is unknown.”

**7. Distinguish the three Module 3 experiments.** [slide 33](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_027)–[slide 36](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_029), [slide 38](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_031)–[slide 44](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_036), [slide 47](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_037). The fixed-transcript [ontology comparison](../module_3/lab/compare.py) filters types and relations and saves a projection. Browser ingestion writes live graph memory and hydrates matched entities from SQLite. The separate [validator experiment](../scripts/instructor.py) explicitly chooses the drop/raise behavior. On the first comparison, label each by **input, writes, and where to look**. Preserve the current disclosure that optional Wikimedia enrichment is a cached lab result, not a live graph write. **Check:** a learner does not search Live memory for an extractor-only snapshot or infer a validation mode from a different run.

**8. Do not let `TOUCHED` become proof that a tool read a row.** [slide 49](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_039)–[slide 52](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_code_m4_tools), [slide 58](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_044). The [recording loop](../module_4/app/reasoning.py) computes Customer/Plan references for the selected case, then supplies that set for each collected call. It does not derive an independent database dependency for each operation. Label this **case context**. For “Why did you issue that refund?” have learners inspect the tool output, executed SQL where captured, current policy, and action receipt. A trace records actions and results; it does not expose hidden model reasoning. **Check:** a participant can point to one case-context edge and a separate operation record, and say what each supports.

**9. Name the scorecard probes precisely.** [slide 18](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_017), [slide 82](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_054). Keep the useful “controlled retrieval” framing and private fixtures. The [evaluator](../scripts/eval.py) gives the customer’s name in the identity question; it accepts a message **or** entity ID. The fourth probe asks for an exact prior refusal quote, not execution of a new procedure. A pass requires the expected fields and **at least one** accepted source ID; it does not validate every citation returned. Rename the two cards “Named customer lookup” and “Prior decision quote.” Show one passing and one failing response with the failed check highlighted. **Check:** no inference from 4/4 to customer authentication, general support quality, or refund safety.

**10. Use a real neutral result to teach ablation.** [slide 54](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_041)–[slide 59](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_045), [slide 82](https://docs.google.com/presentation/d/1qBsciAQf7s3BUdQleJJ39-4RDKAoqqoVfodPDDg63z8/edit#slide=id.ram_design_054). Control used 2,712 input tokens and 31.470 seconds; treatment used 3,456 and 33.589 seconds. Attribute these numbers to **one ticket in one prior rehearsal**, not a benchmark. Ask: “Did retrieval change the business action here? What did it cost in this observation?” **Check:** “same action, more context in this run” counts as a successful interpretation.
